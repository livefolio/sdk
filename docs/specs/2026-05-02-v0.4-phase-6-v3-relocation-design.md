# v0.4 Phase 6 — Relocate v0.3 into `parity/`

**Status:** Draft
**Date:** 2026-05-02
**Companion plan:** `docs/plans/2026-05-02-v0.4-phase-6-v3-relocation.md` (TBD)

## Goal

Make `src/` purely v0.4 by moving the entire v0.3 source tree into the parity workspace at `parity/src/v3/`. After this phase, `@livefolio/sdk`'s public surface is the v0.4 API only (`tactical`, `runBacktest`, `Strategy`, `DataFeed`, etc.), and v0.3 lives on solely as the regression target the parity gate compares against.

This replaces the originally-planned phase 6 codemod CLI. There are no v0.3 strategy files in the wild to migrate, so a codemod has no users.

## Why this approach

- **No migration tool needed.** The codemod existed to give v0.3 users a path to v0.4. There are no such users.
- **Cleaner public surface.** No internal/external split, no aliased coexistence, no deprecation dance — `src/index.ts` exports v0.4 and only v0.4.
- **Smaller published package.** v0.3's handle classes, providers, and computations make up the majority of current shipped code. After the move, none of it ships in `dist/`.
- **Preserves the parity gate.** The 1146-day allocation-history regression test keeps running — v0.3 just lives in the workspace where the regression assertions are.
- **Conceptually correct.** v0.3 is now "the reference implementation we regress against," which is exactly what `parity/` is for.

## Boundary verification

A grep over v0.4 modules for imports from v0.3 paths (`handles/`, `client`, `computations/`, `providers/`, `database.types`, `metrics`) produced exactly one cross-cutting consumer: `src/backtest/simulate.ts`. On inspection, `src/backtest/` is not v0.4 — it's the v0.3 `simulate()` / `SimulationHandle` engine. v0.4's equivalent is `src/strategy/run-backtest.ts`. So `src/backtest/` moves to `parity/src/v3/backtest/` along with the rest of v0.3.

After excluding `src/backtest/`, the v0.4 modules (`interfaces/`, `strategy/`, `features/`, `tactical/`, `reference/`, `orders/`, `portfolio/`) have **zero imports** from v0.3. Boundary is clean; no untangling needed.

## File-level changes

### `src/index.ts`

Currently 100% v0.3 exports (`createClient`, all handle classes, `SimulationHandle`, metrics). Rewrite to expose the v0.4 surface:

```ts
// Strategy / runtime
export { runBacktest, reconcile } from './strategy';
export type { Strategy, Features, BacktestResult, BacktestSnapshot } from './strategy';

// Interfaces
export type {
  Calendar, DataFeed, Executor, FeatureCache,
  Portfolio, Position, Order, Fill,
  AssetId, AssetRef, DateRange, DailyBar, Series,
} from './interfaces';

// Reference implementations
export { USEquityCalendar } from './reference/us-equity-calendar';
export { MemoryFeatureCache } from './reference/memory-feature-cache';
export { BacktestExecutor } from './reference/backtest-executor';

// Tactical dialect
export * as tactical from './tactical';
export type { TacticalSpec, TacticalFeatureSpec, RuleNode, AssetRef as TacticalAssetRef } from './tactical';

// Features library
export * as features from './features';

// Portfolio helpers
export { applyFills, applyOrders } from './portfolio';
```

Subpath exports (`@livefolio/sdk/tactical`, `@livefolio/sdk/features`, etc.) keep working via the existing alias rules in `parity/vitest.config.ts` — they resolve to `../src/<subpath>/index.ts` and those barrels stay where they are.

### `parity/src/`

- `parity/src/v3/` — new directory holding the moved tree.
- `parity/src/strategy.ts` — `import { LivefolioClient, StrategyHandle } from '@livefolio/sdk'` becomes `import type { LivefolioClient } from './v3/client'; import { StrategyHandle } from './v3/handles/strategy';`. v0.4 imports from `@livefolio/sdk/tactical` stay unchanged.
- `parity/src/v3-fixture-providers.ts` — imports of `StorageProvider`/`MarketProvider` switch from `@livefolio/sdk` to `./v3/providers/...`.
- `parity/src/extract-history.ts` — uses v0.3 `SimulationHandle` types; switch import to `./v3/backtest/types`. Also uses v0.4 `BacktestResult` — that import stays.
- `parity/src/parity.test.ts` — composes both sides; v0.3 imports point at `./v3`, v0.4 imports stay at `@livefolio/sdk`/`@livefolio/sdk/tactical`.

### `package.json`

- Bump `version` from `0.3.7` to `0.4.0`. This relocation is the breaking change — root `@livefolio/sdk` now exports a different surface.
- `files: ["dist"]` already prevents v0.3 source from shipping; no change needed there.

### `tsup.config.ts`

`entry: ['src/index.ts']` is unchanged. Just rebuilds against the new barrel.

### `vitest.config.ts` (root)

The root config aliases `@livefolio/sdk` → `src/index.ts` and `@livefolio/sdk/*` → `src/*/index.ts`. After the move, the alias still works for v0.4 subpaths. v0.3 subpaths (`@livefolio/sdk/handles/...`) are no longer importable — but nothing in the v0.4 tree imports them, and `parity/` uses `./v3/` paths instead. Config unchanged.

### `parity/vitest.config.ts`

Same aliases as root config — unchanged. Tests under `parity/src/v3/**` resolved via normal relative imports.

## Test-suite preservation

All co-located v0.3 tests (`src/handles/*.test.ts`, `src/computations/*.test.ts`, `src/backtest/*.test.ts`, `src/metrics/*.test.ts`, `src/client.test.ts`) move with their source. `parity/vitest.config.ts` already has `include: ['src/**/*.test.ts']` so they are picked up in the parity workspace's test run.

Effect on `npm test` (sdk root):
- Before: ~runs both v0.3 and v0.4 tests, plus parity tests via the workspace alias.
- After: runs only v0.4 tests in `src/`. v0.3 tests run from the parity workspace via `cd parity && npm test`.

The combined sequence `cd sdk && npm test && cd parity && npm test && cd ../yfinance && npm test` continues to be the full regression check.

## Migration mechanics

`git mv` preserves history per file. The script outline:

```
git mv src/client.ts        parity/src/v3/client.ts
git mv src/client.test.ts   parity/src/v3/client.test.ts
git mv src/handles          parity/src/v3/handles
git mv src/providers        parity/src/v3/providers
git mv src/computations     parity/src/v3/computations
git mv src/backtest         parity/src/v3/backtest
git mv src/metrics          parity/src/v3/metrics
```

Internal imports inside the moved tree are already relative (`../handles/...`, `./types`, etc.) and stay valid after a directory rename. The only edits are:

1. Imports in `parity/src/{strategy,extract-history,v3-fixture-providers,parity}.{ts,test.ts}` that pointed at `@livefolio/sdk` for v0.3 types — switch to `./v3/...`.
2. `src/index.ts` — full rewrite to v0.4 surface.

## Acceptance criteria

- [ ] `src/` contains only v0.4 modules. `grep -r "from '\.\./handles\|from '\.\./client\|from '\.\./providers\|from '\.\./computations\|from '\.\./backtest\|from '\.\./metrics" src/` returns nothing.
- [ ] `src/index.ts` exports `runBacktest`, `tactical`, `features`, `Calendar`, `DataFeed`, etc. — v0.4 only. No `createClient`, no `SimulationHandle`, no `TickerHandle`, etc.
- [ ] `parity/src/v3/` contains the moved tree; `git log --follow parity/src/v3/handles/strategy.ts` shows the file's full history.
- [ ] `npm test` (sdk root) green — v0.4 tests pass.
- [ ] `cd parity && npm test` green — v0.3 tests + parity gate all pass.
- [ ] `cd ../yfinance && npm test` green — yfinance peer-dep against the new v0.4 surface still works.
- [ ] `npm run build` produces a `dist/` containing only v0.4 — the bundled output should be substantially smaller than 0.3.7's.
- [ ] `package.json` version is `0.4.0`.
- [ ] No `@livefolio/sdk/handles/*`, `@livefolio/sdk/client`, `@livefolio/sdk/providers/*`, etc. imports anywhere in `src/`, `parity/src/`, or `../yfinance/src/`.

## Out of scope

- **Calendar fix** — separate plan at `docs/plans/2026-05-02-nyse-calendar.md`, deferred until after this relocation.
- **v0.3 deletion** — v0.3 stays alive in `parity/src/v3/` for the parity gate. Outright deletion would also delete the regression test. Out of scope indefinitely.
- **Public API documentation** — once v0.4 is the public surface, README and docs need updating to describe v0.4 idioms. Separate plan.
- **`livefolio migrate` codemod** — cancelled. No v0.3 source files in the wild.
- **Metrics port to v0.4** — `src/metrics/` moves to `parity/src/v3/metrics/`. Re-porting metric computation onto v0.4's `BacktestResult` is a separate plan if/when v0.4 backtest consumers ask for it.

## Risks

- **Hidden v0.3 → v0.4 import**. Boundary check used grep against directory names; a renamed re-export could slip through. Mitigation: after the move, run `tsc --noEmit` from `sdk/`; any unresolved import errors out.
- **Parity gate breaks during the move**. The move is mechanical but several files change at once. Mitigation: stage as one commit per directory move, run tests after each.
- **yfinance package depends on a v0.3 export**. The yfinance repo declares `peer-dep @livefolio/sdk@^0.4.0`. Run yfinance's tests against the post-move sdk before publishing.
- **Bundle includes v0.3 transitively**. `tsup` bundles whatever `src/index.ts` reaches. After the rewrite, only v0.4 is reachable, so v0.3 cannot leak. Verify by inspecting `dist/index.js` for absence of v0.3 symbol names.
