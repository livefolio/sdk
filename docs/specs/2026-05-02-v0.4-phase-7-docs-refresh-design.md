## Goal

After phase 6 relocates v0.3 to `parity/src/v3/`, every user-facing and AI-agent-facing doc in this repo still describes v0.3 idioms. Phase 7 brings the docs into alignment with the v0.4 public surface: `runBacktest`, `tactical.fromSpec`, `DataFeed`, `Calendar`, `FeatureCache`, `Executor` — no `createClient`, no `LivefolioClient`, no `TickerHandle`, no Supabase.

This is not the comprehensive user wiki — that's phase 8 (provisional). Phase 7 is the "make existing docs not lie" work.

## Why this is a phase, not a phase-6 sub-task

The README rewrite alone is a substantial new authoring effort, not a mechanical relocation. AGENTS.md files for the new v0.4 modules don't exist yet and need to be written from scratch. Bundling this into phase 6 would conflate "move code" with "write new docs" in one commit graph, making review and rollback harder.

## Content design

### `README.md` — headline structure

```
# @livefolio/sdk

TypeScript SDK for building tactical allocation strategies. Define a strategy
declaratively as a TacticalSpec, plug in a DataFeed, run a backtest.

## Install
npm install @livefolio/sdk

## Quick start (the canonical example)

import { tactical, runBacktest, USEquityCalendar, MemoryFeatureCache } from '@livefolio/sdk';
import type { TacticalSpec } from '@livefolio/sdk/tactical';
import { YfinanceDataFeed } from '@livefolio/datafeed-yfinance';

const spec: TacticalSpec = {
  kind: 'tactical/v1',
  universe: [
    { id: 'us:SPY', symbol: 'SPY' },
    { id: 'us:QQQ', symbol: 'QQQ' },
    { id: 'us:IEF', symbol: 'IEF' },
  ],
  rebalance: { frequency: 'Weekly' },
  features: [
    { id: 'spy_price', kind: 'price', asset: { id: 'us:SPY', symbol: 'SPY' } },
    { id: 'spy_sma200', kind: 'sma', asset: { id: 'us:SPY', symbol: 'SPY' }, period: 200 },
  ],
  rules: {
    op: 'if',
    cond: { op: 'gt', left: { ref: 'spy_price' }, right: { ref: 'spy_sma200' } },
    then: { op: 'allocate', weights: { 'us:SPY': 0.6, 'us:QQQ': 0.4 } },
    else: { op: 'allocate', weights: { 'us:IEF': 1.0 } },
  },
};

const strategy = tactical.fromSpec(spec);
const result = await runBacktest({
  strategy,
  dataFeed: new YfinanceDataFeed(),
  calendar: new USEquityCalendar(),
  featureCache: new MemoryFeatureCache(),
  range: { from: new Date('2020-01-01'), to: new Date('2024-12-31') },
});

console.log(result.snapshots.at(-1));

## Concepts

### TacticalSpec
A declarative JSON-shaped strategy: universe, features, rebalance schedule,
and a rule tree. The same spec is portable across runtimes — pass it to a
backtester today, a paper-trader tomorrow.

### DataFeed
Anything that can answer "give me OHLCV bars for asset X over date range Y".
We ship `@livefolio/datafeed-yfinance`. Implement your own for proprietary feeds.

### Calendar
Trading-day arithmetic. `USEquityCalendar` ships in the box. Pluggable for
non-US exchanges (forthcoming — see `docs/plans/2026-05-02-nyse-calendar.md`).

### FeatureCache
Indicator results are content-addressed by `(feature spec, asset, date)`.
`MemoryFeatureCache` ships; bring your own for cross-process caching.

### Executor
The backtest executor records orders/fills/portfolio snapshots. Swap for a
live broker adapter in production.
```

## Risks

- **README example drifts from real surface.** If the README's quick-start example doesn't compile against the actual v0.4 exports, anyone trying to follow it gets a broken first impression. Mitigation: the quick-start example must be runnable verbatim. Save it as `scripts/v04-readme-example.ts` and run it as part of the phase-7 acceptance check; commit only when it passes.
- **AGENTS.md tree drift over time.** As v0.4 evolves, sub-AGENTS.md files become stale. This is a recurring risk, not specific to phase 7. No mitigation here — that's a docs-hygiene practice, not a phase deliverable.
- **Sibling repo lag.** yfinance's README + peer-dep edits live in a different repo. If we ship phase 6 + 7 here without the yfinance commit, anyone consuming yfinance gets mixed signals. Mitigation: the yfinance commit lands the same day as phase 6's version bump, and phase 7 's acceptance checklist explicitly verifies it.
