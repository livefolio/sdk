Naming conventions: kebab-case file names for multi-word; co-located `*.test.ts`; module barrels via `index.ts`. The `src/features/indicators/` subfolder mirrors the v0.3 `src/computations/` layout one-to-one so the parity story (phase 5) is easy to read.

Conventions: ES module imports are extensionless, `strict: true` plus `noUncheckedIndexedAccess: true` mean every array/Map index access produces `T | undefined` and must be narrowed. Tests use Vitest's `vi.fn()` for mocks; no Supabase, no real network calls.

**Series shape.** All v0.4 indicators consume and produce `Series = ReadonlyArray<{ t: Date; v: number }>` (defined in `src/interfaces/types.ts`). The v0.3 `DailyBar = { date: string; value: number }` shape is *not* used in the new code path; conversion happens at the boundary (`barsToSeries` extracts `close` by default, matching the v0.4 spec § "OHLCV field selection" decision that single-input indicators are close-only in this phase).

**Async-features contract.** Phase 1 declared `Strategy.features` as sync. Phase 2 widens it to `F | Promise<F>` so strategies can `await runtime.compute(...)` inside. Existing sync strategies are unaffected because TypeScript's union allows the narrower type. `runBacktest` `await`s the result unconditionally.

```ts
import type { Bar, Series } from '../interfaces/types';

export type BarField = 'open' | 'high' | 'low' | 'close' | 'volume';

export async function collectBars(it: AsyncIterable<Bar>): Promise<Bar[]> {
  const out: Bar[] = [];
  for await (const b of it) out.push(b);
  return out;
}

export function barsToSeries(bars: ReadonlyArray<Bar>, field: BarField = 'close'): Series {
  const out: { t: Date; v: number }[] = [];
  for (const b of bars) out.push({ t: b.t, v: b[field] });
  return out;
}

export function seriesAt(series: Series, t: Date): number | undefined {
  if (series.length === 0) return undefined;
  const target = t.getTime();
  // binary search for largest index where series[i].t <= target
  let lo = 0;
  let hi = series.length - 1;
  let ans = -1;
  while (lo <= hi) {
    const mid = (lo + hi) >>> 1;
    if (series[mid]!.t.getTime() <= target) {
      ans = mid;
      lo = mid + 1;
    } else {
      hi = mid - 1;
    }
  }
  return ans < 0 ? undefined : series[ans]!.v;
}
```

```ts
import type { Series } from '../../interfaces/types';

export function sma(series: Series, period: number): Series {
  if (period <= 0) throw new Error(`sma: period must be positive, got ${period}`);
  if (series.length < period) return [];
  const out: { t: Date; v: number }[] = [];
  let sum = 0;
  for (let i = 0; i < period; i++) sum += series[i]!.v;
  out.push({ t: series[period - 1]!.t, v: sum / period });
  for (let i = period; i < series.length; i++) {
    sum += series[i]!.v - series[i - period]!.v;
    out.push({ t: series[i]!.t, v: sum / period });
  }
  return out;
}
```

```ts
import type { Series } from '../../interfaces/types';

export function ema(series: Series, period: number): Series {
  if (period <= 0) throw new Error(`ema: period must be positive, got ${period}`);
  if (series.length < period) return [];
  const k = 2 / (period + 1);
  const out: { t: Date; v: number }[] = [];
  let sum = 0;
  for (let i = 0; i < period; i++) sum += series[i]!.v;
  let prev = sum / period;
  out.push({ t: series[period - 1]!.t, v: prev });
  for (let i = period; i < series.length; i++) {
    prev = series[i]!.v * k + prev * (1 - k);
    out.push({ t: series[i]!.t, v: prev });
  }
  return out;
}
```

```ts
import type { Series } from '../../interfaces/types';

export type ReturnMode = 'pct' | 'abs';

export function returnSeries(series: Series, period: number, mode: ReturnMode = 'pct'): Series {
  if (period <= 0) throw new Error(`returnSeries: period must be positive, got ${period}`);
  if (series.length <= period) return [];
  const out: { t: Date; v: number }[] = [];
  for (let i = period; i < series.length; i++) {
    const curr = series[i]!.v;
    const prev = series[i - period]!.v;
    const v = mode === 'abs' ? curr - prev : (curr - prev) / prev;
    out.push({ t: series[i]!.t, v });
  }
  return out;
}
```

## Task 3: Feature spec, paramsHash, and `defineFeature` registry

**Goal:** Land the type surface and registry that phase 3's tactical dialect dispatches through. A `FeatureSpec` is a discriminated-union description of a feature to compute. `defineFeature(kind, compute)` registers a synchronous compute function `(series, params) => Series` against a kind. `paramsHash(spec)` produces a stable content hash used to key `FeatureCache` entries.

**Files:**
- Create: `src/features/spec.ts`
- Create: `src/features/spec.test.ts`

**Acceptance Criteria:**
- [ ] `FeatureSpec` is a discriminated union over `kind` covering the six v0.4 indicators plus `'price'` (identity passthrough — emits the underlying close series unchanged).
  ```ts
  type FeatureSpec =
    | { kind: 'price' }
    | { kind: 'sma'; period: number }
    | { kind: 'ema'; period: number }
    | { kind: 'rsi'; period: number }
    | { kind: 'return'; period: number; mode?: ReturnMode }
    | { kind: 'volatility'; period: number }
    | { kind: 'drawdown'; period: number };
  ```
  All variants are single-input (one underlying series). Multi-input feature kinds (Bollinger, ATR, VWAP, cross-feature comparisons) are deferred to phase 3+ where they need additional spec-resolution machinery; `defineFeature` is intentionally narrow at this phase.
- [ ] `paramsHash(spec: FeatureSpec): string` — returns a deterministic string that depends only on the spec's logical content (key order, omitted optional fields treated identically). Implementation: serialize via a sorted-key JSON walk, then hash with a stable algorithm. v0.4 uses the **string itself** (no hash) because the spec is small and deterministic JSON is sufficient — `paramsHash` returns `JSON.stringify(canonicalize(spec))`. Documented limitation: collisions are impossible because we use the raw canonical string. Function exists so callers don't depend on the encoding choice; future changes can swap in SHA-256 without breaking the contract.
- [ ] `defineFeature<K>(kind: K, compute: (series: Series, spec: Extract<FeatureSpec, { kind: K }>) => Series): void` — registers a compute function. Calling `defineFeature` twice for the same kind throws (no silent override).
- [ ] `getFeatureCompute(kind: FeatureSpec['kind']): ((series: Series, spec: FeatureSpec) => Series)` — looks up a registered compute. Throws if the kind is unknown, surfacing the bug at runtime instead of silently returning empty data.
- [ ] At module load, the seven built-in kinds are auto-registered (price / sma / ema / rsi / return / volatility / drawdown). The registration code lives in `spec.ts` (no separate side-effect file).
- [ ] Tests: paramsHash determinism (two specs with same content → same hash; field-order-different → same hash; period-different → different hash), defineFeature throws on duplicate, getFeatureCompute returns the right function for each built-in kind and produces values consistent with calling the indicator function directly, getFeatureCompute throws on unknown kind.

```ts
import type { Series } from '../interfaces/types';
import { sma } from './indicators/sma';
import { ema } from './indicators/ema';
import { rsi } from './indicators/rsi';
import { returnSeries, type ReturnMode } from './indicators/return';
import { volatility } from './indicators/volatility';
import { drawdown } from './indicators/drawdown';

export type FeatureSpec =
  | { kind: 'price' }
  | { kind: 'sma'; period: number }
  | { kind: 'ema'; period: number }
  | { kind: 'rsi'; period: number }
  | { kind: 'return'; period: number; mode?: ReturnMode }
  | { kind: 'volatility'; period: number }
  | { kind: 'drawdown'; period: number };

export type FeatureKind = FeatureSpec['kind'];

type ComputeFn = (series: Series, spec: FeatureSpec) => Series;

const registry = new Map<FeatureKind, ComputeFn>();

export function defineFeature<K extends FeatureKind>(
  kind: K,
  compute: (series: Series, spec: Extract<FeatureSpec, { kind: K }>) => Series,
): void {
  if (registry.has(kind)) {
    throw new Error(`defineFeature: kind "${kind}" is already registered`);
  }
  registry.set(kind, compute as ComputeFn);
}

export function getFeatureCompute(kind: FeatureKind): ComputeFn {
  const fn = registry.get(kind);
  if (!fn) throw new Error(`getFeatureCompute: unknown feature kind "${kind}"`);
  return fn;
}

function canonicalize(value: unknown): unknown {
  if (value === null || typeof value !== 'object') return value;
  if (Array.isArray(value)) return value.map(canonicalize);
  const obj = value as Record<string, unknown>;
  const sorted: Record<string, unknown> = {};
  for (const k of Object.keys(obj).sort()) {
    if (obj[k] === undefined) continue;
    sorted[k] = canonicalize(obj[k]);
  }
  return sorted;
}

export function paramsHash(spec: FeatureSpec): string {
  return JSON.stringify(canonicalize(spec));
}

defineFeature('price', (series) => series);
defineFeature('sma', (series, spec) => sma(series, spec.period));
defineFeature('ema', (series, spec) => ema(series, spec.period));
defineFeature('rsi', (series, spec) => rsi(series, spec.period));
defineFeature('return', (series, spec) => returnSeries(series, spec.period, spec.mode));
defineFeature('volatility', (series, spec) => volatility(series, spec.period));
defineFeature('drawdown', (series, spec) => drawdown(series, spec.period));
```

## Task 4: FeatureRuntime — orchestrates DataFeed → indicator → FeatureCache

**Goal:** A class that owns a `DataFeed` + `FeatureCache` + range/freq, and exposes one async method: `compute(spec, asset): Promise<Series>`. On call: build the canonical `FeatureKey`, try cache hit; on miss, fetch bars over the runtime's range, project to `Series`, dispatch through `getFeatureCompute(spec.kind)`, store in cache, return.

This is the building block strategy authors close over to make `Strategy.features()` ergonomic, and what `tactical.fromSpec` (phase 3) will use internally.

**Files:**
- Create: `src/features/runtime.ts`
- Create: `src/features/runtime.test.ts`

**Acceptance Criteria:**
- [ ] Constructor: `new FeatureRuntime({ dataFeed, featureCache, range, freq, field? })`. `field` defaults to `'close'`.
- [ ] `compute(spec: FeatureSpec, asset: Asset): Promise<Series>` — idempotent: identical (spec, asset) calls within the lifetime of the runtime hit either the in-process memoization or the FeatureCache; the underlying DataFeed is invoked **at most once** per (asset, range, freq) combination per runtime instance, regardless of how many features are derived from it.
- [ ] Cache key shape (matches `interfaces/feature-cache.ts`):
  ```ts
  {
    feature: spec.kind,
    paramsHash: paramsHash(spec),
    scope: { kind: 'asset', asset: asset.id },
    range: this.range,
    freq: this.freq,
  }
  ```
- [ ] If `featureCache.get(key)` returns a series, return it. If undefined, compute, then `featureCache.set(key, series)` and return.
- [ ] Implementation note: bars-fetch is the expensive op. The runtime keeps an in-process `Map<string, Promise<Series>>` keyed by `${asset.id}|${freq}|${range}` so concurrent `compute()` calls for the same underlying bars share one fetch. The bars are projected to a `Series` (via `barsToSeries`) and that base series is reused across all derived features.
- [ ] Errors propagate: a failed bars fetch (rejected promise) propagates out of `compute`. Cache misses + indicator errors propagate.
- [ ] Tests:
  - cache miss → fetches bars, computes, stores in cache, returns series
  - cache hit → does NOT fetch bars (DataFeed.bars `vi.fn()` not called)
  - two features over same asset → DataFeed.bars called exactly once
  - unknown spec.kind → throws (delegated to `getFeatureCompute`)

**Verify:** `npm test -- src/features/runtime.test.ts` → all green.

```ts
import type { Asset, DateRange, Frequency, Series } from '../interfaces/types';
import type { DataFeed } from '../interfaces/data-feed';
import type { FeatureCache, FeatureKey } from '../interfaces/feature-cache';
import { collectBars, barsToSeries, type BarField } from './series-utils';
import { getFeatureCompute, paramsHash, type FeatureSpec } from './spec';

export type FeatureRuntimeOptions = {
  dataFeed: DataFeed;
  featureCache: FeatureCache;
  range: DateRange;
  freq: Frequency;
  field?: BarField;
};

export class FeatureRuntime {
  private readonly opts: FeatureRuntimeOptions;
  private readonly basePromises = new Map<string, Promise<Series>>();

  constructor(opts: FeatureRuntimeOptions) {
    this.opts = { field: 'close', ...opts };
  }

  private baseKey(asset: Asset): string {
    const r = this.opts.range;
    return `${asset.id}|${this.opts.freq}|${r.from.toISOString()}|${r.to.toISOString()}|${this.opts.field}`;
  }

  private async baseSeries(asset: Asset): Promise<Series> {
    const k = this.baseKey(asset);
    let p = this.basePromises.get(k);
    if (p) return p;
    p = (async () => {
      const bars = await collectBars(this.opts.dataFeed.bars(asset, this.opts.range, this.opts.freq));
      return barsToSeries(bars, this.opts.field);
    })();
    this.basePromises.set(k, p);
    return p;
  }

  private cacheKey(spec: FeatureSpec, asset: Asset): FeatureKey {
    return {
      feature: spec.kind,
      paramsHash: paramsHash(spec),
      scope: { kind: 'asset', asset: asset.id },
      range: this.opts.range,
      freq: this.opts.freq,
    };
  }

  async compute(spec: FeatureSpec, asset: Asset): Promise<Series> {
    const key = this.cacheKey(spec, asset);
    const cached = await this.opts.featureCache.get(key);
    if (cached) return cached;
    const base = await this.baseSeries(asset);
    const compute = getFeatureCompute(spec.kind);
    const result = compute(base, spec);
    await this.opts.featureCache.set(key, result);
    return result;
  }
}
```
