## Naming convention

Phase 4 set the convention **repo = vendor, package = interface**: repo `yfinance` ships `@livefolio/datafeed-yfinance`. Future Alpaca repo (`alpaca/`) will ship `@livefolio/datafeed-alpaca` and `@livefolio/executor-alpaca` from one tree, sharing internal vendor-client code. The v0.4 spec was updated to match — see `docs/specs/2026-04-29-v0.4-multi-repo-interface-design.md` § Repository and package layout, including the explicit naming-convention paragraph. Rationale: vendors that ship multiple capabilities (Alpaca = data + execution) lose the type signal under a flat "adapter" namespace.

## What landed

Eight tasks, one commit each, 39 passing tests:

1. Repo scaffold (TS + ESM + tsup + vitest + eslint + prettier; peer-dep `@livefolio/sdk@^0.4.0`; `file:../sdk` for local dev).
2. `assetToYahooSymbol` — pure resolver with class-share dot→hyphen handling.
3. `fetchYahooBars` — `yahoo-finance2` wrapper with **DST-agnostic structural completeness filter** (drop the last bar iff its UTC time-of-day differs from the modal time-of-day of preceding bars) and **full adjustment** (`adjclose/close` ratio applied uniformly to OHL so bars are total-return-adjusted; volume stays raw).
4. `BarCache` — range-aware in-memory cache; panics on partial-overlap merge (YAGNI).
5. `YfinanceDataFeed` — implements `DataFeed.bars`, in-flight dedup for concurrent calls, no `fundamentals`/`events` stubs (preserves `'x' in feed` feature-detection).
6. Recorded fixtures — `npm run fixtures:record` (manual, hits Yahoo once); committed SPY/QQQ/IEF 2020-2024 JSON; `fixtureFetcher` test helper.
7. End-to-end integration test — SMA(20) crossover SPY ↔ IEF via `tactical.fromSpec` + `runBacktest` against fixtures, plus a deterministic-rerun assertion.
8. Publish prep — README, AGENTS.md, CLAUDE.md, LICENSE, `npm pack --dry-run` clean.

Final phase verification: `tsc`, lint, format, `npm test` (39/39 across 6 files), `npm run build`, `npm pack --dry-run` all green.

## Decisions made off the original plan

Caught and folded in during execution; documented in the new repo's plan and code:

- `yahoo-finance2` `^2` → `^3` (v3 is where the `chart` API lives; verified empirically).
- SDK consumed via tsconfig `paths` + vitest `resolve.alias` for subpath imports (`@livefolio/sdk/tactical`, `/strategy`, `/features`, `/reference`, `/interfaces`) — workaround for the SDK's main barrel not yet re-exporting the v0.4 surface. Drops out when SDK 0.4.0 ships proper barrel exports.
- DST-boundary test fixture rewritten from "3 pre + 3 post" to "2 pre + 4 post" so the post-DST shape dominates the modal — caught a real internal inconsistency in the original plan.
- **Bars are fully total-return-adjusted, not just close.** Initial implementation used `close = adjclose, OHL raw` which is internally inconsistent on dividend days. Fixed in commit `11df4a2` to apply `adjclose/close` uniformly to OHL. README + CLAUDE.md document that this adapter is **backtest-only** — pairing with a live broker executor isn't a supported configuration (use the broker's own feed for live).
